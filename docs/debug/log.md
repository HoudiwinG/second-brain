окно, процесс остался жив минимум 3 секунды и был принудительно остановлен.
Файл `data\flutter_assets\assets\tray_icon.ico` существует рядом с `.exe`.
Визуально меню/иконка трея не проверялись.

Формальный вердикт исходного ревью остаётся **FAIL** до повторной проверки
agent-2; stage-03 не начат.

## Паттерны ошибок

Обновляется в конце каждого ревью. Список повторяющихся классов ошибок
и предложения по улучшению промпта/архитектуры.

- Валидация API пакетов перед написанием кода. Big-version-мутации (riverpod 3,
  drift 2.35, tray_manager 0.8, flutter 3.47) сломали 4 контрактом в ходе этапа.
  Рекомендация: при первом применении пакета — читать его доки/примеры в pub-кэше
  до написания вызовов.
- **«Закрыто» без артефакта проверки (повторяется: TD-06 → ADR-009 → R00-001).**
  Критерий объявляется выполненным по наличию кода/конфига, а не по результату
  прогона; изменения при этом могут быть незакоммичены. Улучшение процесса:
  в шаблоне stage-XX.md у критерия приёмки требовать ссылку на CI-run или лог
  команды; статус `done` запрещён при непустом `git status --short`.
- **Правка манифеста зависимостей без `pub get` (TD-07 → R00-002).**
  `pubspec.yaml` и `pubspec.lock` расходятся; проверки после правки не запускались.
  Улучшение: добавить в CI `flutter pub get --enforce-lockfile` и в чек-лист
  агента-1 — обязательный `pub get` + коммит lock после любой правки зависимостей.
- **Платформенные ограничения плагина не проверены (R00-003).**
  На Windows трей грузит иконку через `LoadImage(IMAGE_ICON)` — PNG не
  поддерживается, ошибка молчаливая. Улучшение: перед использованием плагина
  читать его платформенную реализацию и пример; для файлов-ассетов проверять
  формат под целевую ОС.
- **Документация фиксирует намерение, а не факт (R00-004, R00-006, R00-007).**
  В stage-00.md остались формулировки от отвергнутого варианта (`createAll`
  safe-guard), число ключей ARB не совпадает (33 vs 31), тест описан шире, чем
  реализован, context.md описывает другую машину. Улучшение: при закрытии
  техдолга перечитывать затронутые абзацы отчёта этапа, а не только добавлять
  новый текст.
- **Feature-specific логика в `lib/app` (R00-008).**
  Контроллер настроек живёт вне `features/settings`; при росте фич app-слой
  станет свалкой. Улучшение: зафиксировать в ADR-008 правило «app — только
  композиция/MaterialApp» и переносить состояние в фичу.
- **Перемещение файла без обновления ссылок в ADR/документации (R00-008 → R00-013).**
  Контроллер перенесён в `features/settings/application`, но ADR-001 продолжает
  указывать `lib/app/settings_controller.dart`. Улучшение: при перемещении
  файла выполнять `grep` по старому пути в `lib/`, `test/`, `docs/` и обновлять
  ADR сразу в том же коммите.
- **Исправление ошибки без regression-теста (R00-009 → R00-014).**
  Откат настроек при ошибке репозитория реализован, но failure-путь не покрыт
  тестом и не показывает пользователю локализованное сообщение. Улучшение:
  для каждого исправления ошибки добавлять тест, воспроизводящий исходный
  сценарий (в т.ч. через override провайдера с падающей реализацией).
- **Разработчик выставляет вердикт за ревьюера (R00-015).**
  PASS-блок «Повторное ревью» оформлен от имени agent-2, но добавлен коммитом
  agent-1; на нём основаны PASS-формулировки в stage-00/context/INDEX/tech-debt.
  Улучшение: журнал `stage-XX-review.md` и строку «Ревьюер» заполняет только
  agent-2; self-check разработчика — отдельный раздел с явной атрибуцией;
  в шаблон ревью добавить поле «кто внёс запись» и запретить разработчику
  менять вердикт.
- **«Запуск подтверждён» по артефакту сборки (R00-016, повтор R00-001).**
  Наличие `.exe` или зелёного CI-job'а `build` не доказывает запуск GUI.
  Улучшение: для критериев «приложение запускается/работает» прикладывать лог
  или скриншот ручного прогона; в отчёте различать «собрано» и «запущено».
- **`setState` с async-замыканием (stage-01).**
  `setState(() => _future = _load())` возвращает `Future`, Flutter падает с
  assertion «setState() callback argument returned a Future». Улучшение: в
  `setState` использовать блок `{ ... }`, а асинхронную работу выполнять до
  вызова; добавить widget-тест на обновление списка после сохранения.
- **Освобождение `TextEditingController` до конца анимации диалога (stage-01).**
  После `await showDialog` маршрут ещё анимируется; `dispose` контроллера даёт
  «used after being disposed». Улучшение: владение контроллерами — в
  stateful-виджете диалога, а не в вызывающем экране.
- **SQLite-операции в widget-тестах не завершаются в fake async (stage-01).**
  `pumpAndSettle` не ждёт реальный event loop. Улучшение: использовать
  `tester.runAsync` с паузой и затем `pumpAndSettle`; проверять результат и в
  БД, и в UI.
- **Платформенный API проверять по исходникам пакета, а не по памяти
  (stage-02).** `PhysicalKeyboardKey.logicalKey` отсутствует, а
  `LogicalKeyboardKey` переопределяет `==`, поэтому `const Set` с ним не
  компилируется. Улучшение: перед использованием типа читать API в pub-кэше;
  для множеств с объектами — `final`, не `const`.
- **Фоновые таймеры ломают widget-тесты (stage-02).** `Timer.periodic` в
  провайдере, созданном на всех платформах, оставляет pending timer и мешает
  `pumpAndSettle`. Улучшение: создавать планировщик только на целевой
  платформе и переопределять провайдер в тестах.
- **Форматирование всего дерева на Windows — отдельный риск (stage-02).**
  `dart format` меняет legacy switch-выражения и создаёт шум в файлах, не
  относящихся к этапу. Улучшение: не включать форматирование в CI без
  отдельного pass и фиксации версии formatter (TD-20).
- **Line-ending-шум в generated-файлах (stage-02).** `git status` показывает
  изменённый `generated_plugin_registrant.h`, но `git diff --numstat` не даёт
  контентных строк. Улучшение: проверять numstat и откатывать файлы без
  реальных изменений, сохраняя регистрацию новых плагинов.
- **Относительный путь к ассету в нативном плагине (R02-001, развитие
  R00-003).** `tray_manager` передаёт `assets/tray_icon.ico` в
  `LoadImage(..., LR_LOADFROMFILE)`, а путь разрешается от текущего рабочего
  каталога. При запуске из проводника/ярлыка он не совпадает с корнем
  репозитория; плагин при этом не сообщает об ошибке. Улучшение: для нативных
  файловых API использовать абсолютный путь от `Platform.resolvedExecutable`
  (или временный файл из `rootBundle`), проверять существование файла и
  считать функцию успешной только при подтверждённой готовности ресурса;
  smoke запускать с рабочим каталогом `.exe`, а не из корня проекта.
- **Ошибка side-effect проглочена, а состояние изменено (R02-002).**
  `ReminderNotifier.show` ловит все ошибки и возвращает `void`; scheduler
  считает показ успешным и ставит `reminder_sent_at`. Ошибка внешнего
  side-effect (toast, запись файла, сеть) должна возвращать явный результат
  или пробрасываться, а состояние «доставлено» — меняться только после
  успеха. Улучшение: `Future<bool>`/`Result` + тест с падающим notifier.
- **Асинхронный результат применения настройки проигнорирован (R02-003).**
  `unawaited(apply(...))` при старте и ранний `return true` при совпадении
  состояния скрывают, что фактическая регистрация не применилась. Улучшение:
  `await` с проверкой результата, fallback и видимое сообщение; состояние UI
  должно отражать фактическую регистрацию, а не только сохранённое значение.
- **Границы интервалов без явной семантики (R02-005, R02-008).**
  `to` в финансовом запросе включителен, а дашборд передаёт начало следующего
  месяца; `dayEnd` считается как 24 часа, а не как следующий локальный
  полночь. Улучшение: в контракте фиксировать `[from, to)` или `[from, to]`,
  для календарных границ использовать конструкторы `DateTime`, а не
  `Duration(days: 1)`; добавлять тесты на границу и DST.
- **Тесты только happy-path для внешних эффектов (R02-007).** Наличие
  `Result` и зелёных тестов не гарантирует обработку падения провайдера,
  notifier или миграции. Улучшение: для каждого внешнего side-effect
  добавлять failing-реализацию через override и проверять, что состояние
  откатилось/не изменилось.
