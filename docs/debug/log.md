## Паттерны ошибок

Обновляется в конце каждого ревью. Список повторяющихся классов ошибок
и предложения по улучшению промпта/архитектуры.

- Валидация API пакетов перед написанием кода. Big-version-мутации (riverpod 3,
  drift 2.35, tray_manager 0.8, flutter 3.47) сломали 4 контрактом в ходе этапа.
  Рекомендация: при первом применении пакета — читать его доки/примеры в pub-кэше
  до написания вызовов.
- **«Закрыто» без артефакта проверки (повторяется: TD-06 → ADR-009 → R00-001).**
  Критерий объявляется выполненным по наличию кода/конфига, а не по результату
  прогона; изменения при этом могут быть незакоммичены. Улучшение процесса:
  в шаблоне stage-XX.md у критерия приёмки требовать ссылку на CI-run или лог
  команды; статус `done` запрещён при непустом `git status --short`.
- **Правка манифеста зависимостей без `pub get` (TD-07 → R00-002).**
  `pubspec.yaml` и `pubspec.lock` расходятся; проверки после правки не запускались.
  Улучшение: добавить в CI `flutter pub get --enforce-lockfile` и в чек-лист
  агента-1 — обязательный `pub get` + коммит lock после любой правки зависимостей.
- **Платформенные ограничения плагина не проверены (R00-003).**
  На Windows трей грузит иконку через `LoadImage(IMAGE_ICON)` — PNG не
  поддерживается, ошибка молчаливая. Улучшение: перед использованием плагина
  читать его платформенную реализацию и пример; для файлов-ассетов проверять
  формат под целевую ОС.
- **Документация фиксирует намерение, а не факт (R00-004, R00-006, R00-007).**
  В stage-00.md остались формулировки от отвергнутого варианта (`createAll`
  safe-guard), число ключей ARB не совпадает (33 vs 31), тест описан шире, чем
  реализован, context.md описывает другую машину. Улучшение: при закрытии
  техдолга перечитывать затронутые абзацы отчёта этапа, а не только добавлять
  новый текст.
- **Feature-specific логика в `lib/app` (R00-008).**
  Контроллер настроек живёт вне `features/settings`; при росте фич app-слой
  станет свалкой. Улучшение: зафиксировать в ADR-008 правило «app — только
  композиция/MaterialApp» и переносить состояние в фичу.
