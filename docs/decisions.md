## ADR-001: Riverpod как стейт-менеджмент и DI
- **Дата (UTC):** 2026-10-21 19:10
- **Этап:** stage-00
- **Тип:** architecture
- **Автор/агент:** agent-1 (GLM-5.3-Flash-Free)
- **Статус:** accepted

### Контекст
Требуются DI и управление состоянием; важны низкий порог входа для смены
LLM-агента и перспектива роста (мультиаккаунт, фича-флаги, LLM-слой).

### Решение
`flutter_riverpod 3.4.3`. Асинхронные синглтоны (БД, репозиторий настроек) —
через `FutureProvider`; контроллеры UI-настроек — `AsyncNotifier`,
взаимодействие через обычные `Notifier`-паттерны. Тесты переопределяют
провайдеры через `ProviderScope.overrides`.

### Альтернативы
- Bloc/Cubit: богаче, но больше шаблонного кода и выше порог входа для нового агента.
- Только InheritedWidget: без внешних зависимостей, но неудобен как DI и приведёт к утечкам логики в виджеты.

### Последствия
- Положительные: единая точка DI, лёгкий вход, удобные тесты через overrides.
- Отрицательные/риски: Riverpod 3 меняет API между версиями
  (зафиксировано: вместо `valueOrNull` — nullable `value`).
- Влияние на совместимость/миграции: апгрейд мажорной версии Riverpod потребует ADR.

### Затронутые файлы/модули
- lib/app/di.dart, lib/app/settings_controller.dart — все ключевые провайдеры.

### Связанные записи
ADR-002 (Drift), ADR-005 (роутер)

## ADR-002: Локальная БД — Drift (SQLite), схема v1 = только app_settings
- **Дата (UTC):** 2026-10-21 19:12
- **Этап:** stage-00
- **Тип:** architecture / schema
- **Автор/агент:** agent-1
- **Статус:** accepted

### Контекст
Нужна реляционная локальная БД с типизацией, миграциями и будущим FTS5 (этап 1).

### Решение
`drift 2.35.2` + `sqlite3_flutter_libs`; executor — `NativeDatabase.createInBackground`
(запросы вне UI-потока). Схема v1: единственная таблица `app_settings`
(key TEXT PK, value TEXT, updated_at DATETIME) — для проверки механизма миграций.

### Альтернативы
- Hive/Isar: нет SQL и FTS5.
- Прямые запросы sqlite3: нет типизации и миграций.

### Последствия
- Положительные: полный SQL; механизм onCreate/onUpgrade проверен тестом (in-memory).
- Отрицательные/риски: DateTime drift по умолчанию возвращает в локальной зоне —
  сравнивать через `.toUtc()` (зафиксировано в тесте миграций).
- Влияние: schemaVersion=1; этап 1 добавит таблицы + миграцию v1→v2.

### Затронутые файлы/модули
- lib/data/db/app_database.dart, lib/data/repositories/settings_repository.dart.

### Связанные записи
ADR-001 (инъекция БД через Riverpod)

## ADR-003: Секреты — flutter_secure_storage, контракт SecretStore
- **Дата (UTC):** 2026-10-21 19:14
- **Этап:** stage-00
- **Тип:** security
- **Автор/агент:** agent-1
- **Статус:** accepted

### Контекст
Все секреты (LLM-ключи — этап 3, OAuth-токены — этап 6) должны храниться
в зашифрованном системном хранилище (DPAPI/Keychain/Keystore).

### Решение
Интерфейс `SecretStore` (read/write/delete/clear, всё через `Result`) +
`SecureSecretStore` на flutter_secure_storage 11.x. Для тестов —
`InMemorySecretStore`. Секреты никогда не попадают в Drift и логи.

### Альтернативы
- Хранение ключей в файле рядом с БД — не соответствует требованиям ТЗ к безопасности.
- Кастомная CryptoService-обёртка DPAPI — дублирует готовый плагин.

### Последствия
- Положительные: контракт готов к OAuth и LLM-ключам; смена реализации не влияет на клиентов.
- Отрицательные/риски: flutter_secure_storage 11.x удалил опцию
  `encryptedSharedPreferences` на Android — учтено (используем дефолт).
- Влияние на совместимость: интерфейс неизменный, реализация может обновляться.

### Затронутые файлы/модули
- lib/core/secrets/ (secret_store.dart, secure_secret_store.dart, in_memory_secret_store.dart).

### Связанные записи
ADR-004 (Result-контракт)

## ADR-004: Контракт ошибок — sealed AppException + Result<T>
- **Дата (UTC):** 2026-10-21 19:16
- **Этап:** stage-00
- **Тип:** architecture
- **Автор/агент:** agent-1
- **Статус:** accepted

### Контекст
UI не должен зависеть от исключений слоя данных; сети/LLM/интеграции требуют
единый тип ошибок и флаг повторяемости.

### Решение
`Result<T>` (Success/Failure) + иерархия `AppException`
(Validation/Data/Network/Integration/Llm/Unexpected). NetworkException несёт
`retryable`. Слои возвращают Result; исключения пересекают границы слоя только
внутри одной реализации.

### Альтернативы
- Только исключения: обработка в UI хрупкая.
- Свои ошибки у каждого слоя: точнее, но сложнее для смены агента.

### Последствия
- Положительные: исчерпывающая обработка через `when`, безопасное логирование.
- Отрицательные/риски: новый тип ошибки — всегда расширение AppException (один файл).
- Влияние на совместимость: контракт стабильный.

### Затронутые файлы/модули
- lib/core/result/result.dart, lib/core/error/app_exception.dart.

### Связанные записи
ADR-003 (SecretStore поверх Result)

## ADR-005: Навигация — go_router StatefulShellRoute, 11 веток
- **Дата (UTC):** 2026-10-21 19:18
- **Этап:** stage-00
- **Тип:** ux / architecture
- **Автор/агент:** agent-1
- **Статус:** accepted

### Контекст
10 фиче-экранов + «Ещё»; Windows-first — боковая навигация, мобильные — нижняя панель.

### Решение
`go_router 18.1.1` + `StatefulShellRoute.indexedStack`. 11 веток (10 фич + /more),
порядок зафиксирован в enum `FeatureBranch` (контракт навигации).
Широкие окна: NavigationRail со всеми ветками; узкие: NavigationBar из 5
главных (dashboard/notes/tasks/chat/more), остальные доступны через /more.

### Альтернативы
- Drawer: хуже для постоянной навигации на десктопе.
- Кастомный роутер: дублирование зрелого пакета.

### Последствия
- Положительные: состояние каждой ветки сохраняется; переходы между ветками дешёвые.
- Отрицательные/риски: изменение порядка/числа веток меняет индексы — критическое изменение (требует ADR).
- Влияние: новые фичи добавляются в конец enum FeatureBranch.

### Затронутые файлы/модули
- lib/app/feature_directions.dart, lib/app/router.dart, lib/app/more_screen.dart.

### Связанные записи
ADR-001 (роутер предоставляется через Riverpod)

## ADR-006: tray_manager зафиксирован на 0.5.x (нативная сборка 0.6+ отклонена)
- **Дата (UTC):** 2026-10-21 19:20
- **Этап:** stage-00
- **Тип:** dependency / integration
- **Автор/агент:** agent-1
- **Статус:** accepted

### Контекст
Нужен трей Windows (ТЗ модуль 13, STAGE_ONE п.12). tray_manager 0.6+ построен
на nativeapi/cnativeapi с native-assets (CBuilder) — это требует MSVC
C-компилятора даже для `flutter test` без GUI; Visual Studio в окружении нет.

### Решение
Зафиксировали `tray_manager: 0.5.0` (платформенные каналы, без C-сборки).
API совместим с нужным нам набором (setIcon/setToolTip/setContextMenu/TrayListener).

### Альтернативы
- tray_manager 0.8.x: требует C-тулчейн везде, включая тесты — отклонено на этапе 0.
- Другие пакеты трея: менее проверенные.
- Отказаться от трея: нарушение ТЗ.

### Последствия
- Положительные: тесты и analyze работают без установленного MSVC.
- Отрицательные/риски: ветка 0.5 развиваться не будет; после установки VS — миграция на nativeapi-слой (новый ADR).
- Влияние на совместимость: импорт `tray_manager/tray_manager.dart`; смена пакета = новый ADR.

### Затронутые файлы/модули
- pubspec.yaml (пин версии), lib/app/desktop_services.dart.

### Связанные записи
ADR-007 (сборка Windows отложена из-за VS)

## ADR-007: flutter build windows отложен до установки Visual Studio C++
- **Дата (UTC):** 2026-10-21 19:22
- **Этап:** stage-00
- **Тип:** dependency
- **Автор/агент:** agent-1
- **Статус:** accepted (блокер зафиксирован)

### Контекст
Критерий этапа 0 «сборка Windows» требует MSVC toolchain; в окружении его нет
(vswhere не найден, C:\ProgramFiles\Microsoft Visual Studio отсутствует).
Пользователь выбрал сценарий «установить только Flutter SDK».

### Решение
Выполнено всё остальное: `flutter analyze` (0 issues) и `flutter test`
(зелёные) на хост-машине. `flutter build windows` отложен до установки
VS Build Tools с workload «Desktop development with C++».

### Альтернативы
- Тихая установка VS агентом (около 7 ГБ, 20–40 минут): предложено, отклонено пользователем.
- CI-сборка windows в GitHub Actions: вне объёма этапа 0.

### Последствия
- Положительные: блокер явно зафиксирован; остальные проверки этапа не пострадали.
- Отрицательные/риски: критерий сборки подтверждается позже (см. stage-00.md, чек-лист).
- Влияние: этап 0 закрывается как done с оговоркой по критерию сборки.

### Затронутые файлы/модули
- docs/context.md (блокеры), docs/stages/stage-00.md (проверки).

### Связанные записи
ADR-006

## ADR-008: Feature-first структура папок + локализация ARB RU/EN
- **Дата (UTC):** 2026-10-21 19:26
- **Этап:** stage-00
- **Тип:** architecture / ux
- **Автор/агент:** agent-1
- **Статус:** accepted

### Контекст
ТЗ предписывает Clean Architecture + feature-first; RU/EN — из коробки.

### Решение
Слои presentation/domain/data внутри каждой фичи (этап 0: только presentation),
общие виджеты — lib/app/widgets, сервисы — lib/core, инфраструктура — lib/data.
Локализация: l10n.yaml, сгенерированные классы пишутся в физический каталог
lib/l10n/generated (импорты стабильны для любого агента); весь UI-текст —
только ключи ARB (никаких строк-констант в коде UI).

### Альтернативы
- Синтетический пакет `package:flutter_gen/...`: требует настройки анализатора и IDE.
- Хардкод строк: нарушает ТЗ.

### Последствия
- Положительные: вход нового агента упрощён; добавление языка = один новый ARB-файл.
- Отрицательные/риски: `AppLocalizations.of(context)` в сгенерированном коде
  nullable — необходим `!` в точках вызова.
- Влияние: новые ключи добавляются в app_en.arb (template) и app_ru.arb.

### Затронутые файлы/модули
- l10n.yaml, lib/l10n/*, lib/features/*/*/.

### Связанные записи
ADR-005 (навигация использует локализованные метки)
