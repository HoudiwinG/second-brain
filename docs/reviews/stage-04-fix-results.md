## Детали по ключевым находкам

### S04-001 — Google и несколько tool calls

Было: каждое `LlmRole.tool`-сообщение превращалось в отдельный `user`-content,
поэтому два параллельных вызова давали две `user`-реплики подряд.

Стало (`lib/features/llm/data/google_provider.dart`):

- результаты инструментов группируются в последний `user`-content, если он
  состоит только из `functionResponse`;
- текстовая `user`-реплика никогда не смешивается с результатами;
- порядок вызовов сохраняется.

Тест `test/llm_tool_mapping_test.dart` («результаты нескольких вызовов идут
одним user-content») фиксирует: 3 содержимых (`user`, `model`, `user`), во
втором — два `functionResponse` с именами `create_note` и `create_task`.

### S04-003 — аудит

- `ToolRunner._argumentNames` оставляет только ключи, объявленные в схеме
  инструмента; посторонние ключи (в том числе созданные prompt injection) в
  журнал не попадают;
- имя неизвестного инструмента заменяется литералом `unknown`, имя
  зарегистрированного берётся из реестра (`tool.name`), а не из ответа модели;
- `ToolAuditRepository` хранит имена JSON-массивом; чтение поддерживает старый
  формат `a,b` для уже записанных строк.

### S04-004 / S04-005 — приватная задача

`update_task_status` больше не читает задачу отдельно: он вызывает
`setStatusForLlm`, который выполняет единственный `UPDATE` с условиями
приватности и отсутствия удаления. Ноль изменённых строк — всегда
`ValidationException('Задача недоступна')`, поэтому отличить приватную задачу
от несуществующей нельзя, а гонка «проверка → запись» исчезает.
